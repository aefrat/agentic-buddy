Phase 1: Product Identity & Entitlements

5 steps
1.1

Define SKU and Subscription

Create the commercial subscription product (SKU) in the Red Hat subscription system. Maps to entitlements in Candlepin.

PM + Business Tribal knowledge
1.2

Request Engineering ID (EngID)

Add signing keys to cdn-definitions-private, DirectoryLayout to cdn-utils, code to psc-lib, product config to product-service-config-auto (preprod then prod). EngID created automatically after prod MR merges.

Distribution + PSCA product-service-config-auto Documented
1.3

Configure Content Sets

Define content sets in Product Service: label, download URL pattern, architecture, required tags. Flows through to Candlepin entitlement certificates.

Distribution engproduct-cli Tribal knowledge
1.4

Create CDN Directory Layout

Define CDN directory structure in cdn-utils.

dist/ rhivos1/ -- major version (RHIVOS 1.x) 1/ -- rolling: all 1.x content 1.0/ -- GA + all 1.0.z updates + EUS 1.1/ -- GA + all 1.1.z updates + EUS rhivos2/ -- RHIVOS 2.x (same layout) 2/ 2.0/
Distribution cdn-utils Tribal knowledge
1.5

Create rhsm-pulp Repositories

Use cdn-utils to create Pulp repos matching the content sets. Stage repos created first for validation. Cert/key in Bitwarden.

Distribution Tribal knowledge
2

Phase 2: Build Infrastructure

4 steps
2.1

Create Brew Tags

Set up the full tag hierarchy with inheritance. Each release needs 7+ tags (release, gate, candidate, pending, override, build, pesign-build, build-base) plus Z-stream variants.

*-gate <-- RHEL builds flow in (rhel-*-pending inheritance) | v Gator gating tests *-candidate <-- Passed gating, feeds composes | v Scheduled for release *-pending <-- Feeds next release | v Published *-release <-- Fully released builds *-build <-- Buildroot (inherits release + pending via override)
Release Eng Brew (Koji) Documented
2.2

Create Build Targets

Link buildroot to destination tags: *-candidate (standard), *-candidate-pesign (KWF), *-test-pesign (KWF test). Set %dist macro to ".elX_Yiv".

Release Eng Documented
2.3

Create Dist-git Branches

Create rhivos-X-main (development, open policy) and rhivos-X.Y.0 or rhivos-X.Y (release, strict gating with VROOM ticket requirement).

Release Eng Documented
2.4

Configure Gator

Set up gating rules: *-gate to *-candidate (pass) or discard (fail). Post-Dev-Complete: freeze RHEL tag inheritance, require blocker/exception for new builds.

Release Eng Gator Documented
3

Phase 3: Errata Tool Configuration

3 steps
3.1

Create Product / Release

RHIVOS product (225). Create Product Version (PV) for each Y-stream. Define GA release + Z release for each. EUS uses same structure (no separate offering).

Distribution Errata Tool Documented
3.2

Configure Product Listings

Set up product listings required for advisories. Import composes via compose-composedb-import.

Distribution Documented
3.3

Define Advisory Creation Process

Phase 1: Clone RHEL advisories 1:1 ("RHIVOS clone:" prefix). Phase 2: Bulk advisories for remaining builds (up to 100/advisory). RHIVOS-native packages (kernel-automotive, bluechi, qm, AIB) get dedicated advisories.

Distribution Documented
4

Phase 4: Compose Pipeline

3 steps
4.1

Create Release Configs

Add release configuration: compose URL, Koji tag, S3 path, RCM host, Polarion project. Add to release-configs file + gator-run-configs.

Release Eng release-definitions Documented
4.2

Configure ODCS Compose

Set up nightly composes: latest-RHIVOS-X.Y (from *-candidate, switches to *-z-candidate after Dev Complete). RC composes created after Dev Complete from *-candidate.

Release Eng ODCS Documented
4.3

Set Up Internal Distribution

Configure internal channels: webserver (rhivos.auto-toolchain.redhat.com), AWS S3 (auto-product-build-downstream), EC2 download mirror.

Distribution Documented
5

Phase 5: Release Execution

4 steps
5.1

Errata Batch Operations (10-step workflow)

Refresh cache - compare batch vs compose - sync builds - reload file lists - find/drop empty advisories - count status - move NEW_FILES to QE - stage push - move QE to REL_PREP - live push.

Distribution errata-distribution Documented
5.2

CDN Stage Push

Push to CDN staging for validation using et-push --stage on RCM host. Chunking: batch name for 500 or fewer advisories, 100-200 IDs per run for larger batches. Run CCAT checks.

Distribution (ET mgr) et-push --stage Documented
5.3

CDN Live Push

Push staged content to live CDN using et-push --live. Prerequisite: all advisories in PUSH_READY state (auto-promoted from REL_PREP).

Distribution (ET mgr) et-push --live Documented
5.4

Partner Distribution

Push to partner channels: SFTP (accessible under SP) and JFrog Artifactory via sea-bridge service.

Distribution sea-bridge Documented
6
