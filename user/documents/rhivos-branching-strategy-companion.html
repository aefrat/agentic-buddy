1. Executive Summary

Tagging RHIVOS release packages with the correct RHEL tag inheritance has been a knowledge bottleneck - historically only two engineers (Ozan Unsal and Petr Sabata) held the complete procedural knowledge for configuring Brew tags, setting up inheritance chains between RHIVOS and RHEL, and performing the mid-cycle switches that keep the build pipeline sourcing from the right RHEL release.

Petr Sabata documented this knowledge in the RHIVOS Branching Strategy document (v1.0 DRAFT, May 2025). This companion guide makes that knowledge actionable by:

  • Mapping each RHIVOS release to its exact RHEL base version
  • Highlighting the naming convention change between RHIVOS 1.x (RHEL 9, X.Y.Z) and RHIVOS 2.x (RHEL 10, X.Y)
  • Providing a visual inheritance chain diagram
  • Documenting the mid-cycle switch procedure with a timeline
  • Providing a reusable checklist for setting up any future RHIVOS N.0 release
How to read this: This is a companion, not a replacement. Read this for the practical "what to do and when" - read Petr's original for the full rationale and edge cases.

2. RHEL-to-RHIVOS Version Mapping

Each RHIVOS Y-stream release spans two RHEL Y-stream releases (since RHIVOS releases annually and RHEL releases every six months). The gate tag sources builds from the first RHEL release, then switches mid-cycle to the second (the EUS release). The initial RHIVOS N.0 release may follow a simpler pattern.

RHIVOS RHEL Base Gate Sources From %dist Tag Status
1.0 RHEL 9.6 (EUS) rhel-9.6.0-z-pending .el9_6iv Released
1.1 RHEL 9.7 then 9.8 (EUS) rhel-9.7.0-z-pending then rhel-9.8.0-z-pending .el9_8iv In development
1.2 RHEL 9.9 then 9.10 (EUS) rhel-9.9.0-z-pending then rhel-9.10.0-z-pending .el9_10iv Future
2.0 RHEL 10.2 (EUS) rhel-10.2-z-pending .el10_2iv RC3 (CTC at 93%)
2.0.z RHEL 10.2 (z-stream) rhel-10.2-z-pending (post-GA) .el10_2iv Post-GA
2.1 RHEL 10.3 then 10.4 (EUS) rhel-10.3-z-pending then rhel-10.4-z-pending .el10_4iv (projected) Future
Evidence for RHIVOS 2.0 = RHEL 10.2: All RC3 kernel packages use el10_2iv dist tags (e.g. kernel-automotive-6.12.0-211.20.1.el10_2iv), and the gate tag inherited from rhel-10.2-pending before Dev Complete freeze.

3. Naming Convention Change (RHEL 9 vs RHEL 10)

RHEL 10 dropped the third version segment from dist-git branch names and Brew tags. RHIVOS 2.x follows that convention. This affects every tag, target, and branch name.

Component RHIVOS 1.x (RHEL 9 - X.Y.Z) RHIVOS 2.x (RHEL 10 - X.Y)
Dist-git main branch rhivos-1-main rhivos-2-main
Stabilization branch rhivos-1.0.0 rhivos-2.0
Release tag rhivos-1.0.0 rhivos-2.0
Z-stream release tag rhivos-1.0.0-z rhivos-2.0-z
Gate tag rhivos-1.0.0-gate rhivos-2.0-gate
Build target rhivos-1.0.0-candidate rhivos-2.0-candidate
Build tag rhivos-1.0.0-build rhivos-2.0-build
Candidate tag rhivos-1.0.0-candidate rhivos-2.0-candidate
Pending tag rhivos-1.0.0-pending rhivos-2.0-pending
Override tag rhivos-1.0.0-override rhivos-2.0-override
Build-base tag rhivos-1.0.0-build-base rhivos-2.0-build-base
KWF pesign build rhivos-1.0.0-candidate-pesign rhivos-2.0-candidate-pesign
KWF test pesign rhivos-1-newest-test-pesign rhivos-2-newest-test-pesign
Build channel rhel9-power10 rhel10
Build tools source rhel-9-build-tools rhel-10-build-tools
%dist macro (dev) .el9iv .el10iv
%dist macro (branched) .el9_6iv .el10_2iv
Key difference: The trailing .0 in RHEL 9 naming (e.g. rhivos-1.0.0) is gone in RHEL 10. It is rhivos-2.0, not rhivos-2.0.0. This applies to all tags, targets, and dist-git branches.

4. Brew Tag Structure (RHIVOS 2.0 Example)

Each RHIVOS release defines the following set of Brew tags. All exist in two variants: GA and Z-stream. Below is the complete set for RHIVOS 2.0:

Tag GA Variant Z-stream Variant Purpose
Release rhivos-2.0 rhivos-2.0-z Fully released builds (GA or z-stream updates)
Build rhivos-2.0-build rhivos-2.0-z-build Buildroot - inherits release + prev build + override
Pesign Build rhivos-2.0-pesign-build rhivos-2.0-z-pesign-build KWF buildroot (identical to build)
Gate rhivos-2.0-gate rhivos-2.0-z-gate Entry point for all builds - gating input
Candidate rhivos-2.0-candidate rhivos-2.0-z-candidate Builds that passed gating - compose input
Pending rhivos-2.0-pending rhivos-2.0-z-pending Builds scheduled for release
Override rhivos-2.0-override rhivos-2.0-z-override Temporary tagging for dependency chains
Build-base rhivos-2.0-build-base Build groups (srpm-build, build) - one per release

Build Targets

Target Name Buildroot Destination Use
rhivos-2.0-candidate rhivos-2.0-build rhivos-2.0-gate Standard release builds
rhivos-2.0-candidate-pesign rhivos-2.0-pesign-build rhivos-2.0-gate KWF builds
rhivos-2.0-test-pesign rhivos-2.0-pesign-build rhivos-2.0-gate KWF builds (alias)
rhivos-2.0-z-candidate rhivos-2.0-z-build rhivos-2.0-z-gate Z-stream builds (post-GA)

6. Mid-Cycle Switch Procedure

When a RHIVOS Y-stream spans two RHEL releases (e.g. RHIVOS 2.1 spanning RHEL 10.3 and 10.4), the gate and release tag inheritance must be updated mid-cycle. This happens when the odd-numbered RHEL release branches for stabilization.

RHIVOS 2.0 note: As the initial major release based on RHEL 10.2, RHIVOS 2.0 may not have needed a mid-cycle switch - it was based directly on RHEL 10.2 from the start. The mid-cycle switch is more relevant for subsequent releases like RHIVOS 2.1.

RHIVOS 2.1 Example (Projected)

RHEL 10.2 Branch Point (~Feb 2026)
RHIVOS 2.1 development window opens on rhivos-2-main.
Gate initially sources from rhel-10.3-z-pending.
RHEL 10.3 Branch Point (~Aug 2026)
Mid-cycle switch:
1. Update gate inheritance: rhel-10.3-z-pending to rhel-10.4-z-pending
2. Update release tag inheritance: rhel-10.3-z to rhel-10.4-z
3. Update %dist macro in build tags: .el10_4iv
4. Do NOT create an intermediate .el10_3iv dist tag
RHIVOS 2.1 Dev Complete
Freeze:
1. Remove RHEL inheritance from rhivos-2.1 release tag
2. Explicitly list all RHEL packages in the release tag
3. Gating stops auto-sourcing RHEL builds
RHIVOS 2.1 GA (~Jul 2027)
Switch from GA tags to Z-stream tags.
All new work uses rhivos-2.1-z-* tags.

What to Switch

What Before Switch After Switch When
Gate tag RHEL source rhel-10.3-z-pending rhel-10.4-z-pending RHEL 10.3 branch point
Release tag RHEL inheritance rhel-10.3-z rhel-10.4-z RHEL 10.3 branch point
%dist macro .el10iv .el10_4iv RHEL 10.3 branch point (skip 10.3)
RHEL inheritance on release tag Active (auto-source) Removed (explicit list) Dev Complete

7. New Release Setup Checklist

Generalized checklist for setting up any RHIVOS N.Y release. Replace placeholders with actual values. For RHEL 10-based releases, use X.Y naming (no trailing .0).

Template variables:
{VER} = RHIVOS version (e.g. 2.1)
{PREV} = previous release (e.g. 2.0)
{RHEL_BASE} = initial RHEL base (e.g. 10.3)
{RHEL_EUS} = target RHEL EUS release (e.g. 10.4)
{RHEL_MAJOR} = RHEL major version (e.g. 10)

Brew Tags

  • Create GA tags: rhivos-{VER}, rhivos-{VER}-build, rhivos-{VER}-pesign-build, rhivos-{VER}-gate, rhivos-{VER}-candidate, rhivos-{VER}-pending, rhivos-{VER}-override
  • Create Z-stream tags: same set with -z- inserted (e.g. rhivos-{VER}-z, rhivos-{VER}-z-build, ...)
  • Create rhivos-{VER}-build-base inheriting from rhivos-{PREV}-build-base
  • Set build groups on rhivos-{VER}-build-base: duplicate RHEL groups, replace redhat-release with redhat-release-automotive

Tag Inheritance

  • Set rhivos-{VER}-gate to inherit from rhel-{RHEL_BASE}-z-pending
  • Set rhivos-{VER}-gate to inherit from rhivos-{PREV}-z-pending
  • Set rhivos-{VER} release tag to inherit from rhel-{RHEL_BASE}-z and rhivos-{PREV}-z (in that order)
  • Set rhivos-{VER}-build to inherit from release tag + rhivos-{PREV}-build
  • Set rhivos-{VER}-build to inherit from rhivos-{VER}-build-base

Build Targets

  • Create target rhivos-{VER}-candidate: buildroot = rhivos-{VER}-build, destination = rhivos-{VER}-gate
  • Create target rhivos-{VER}-candidate-pesign: buildroot = rhivos-{VER}-pesign-build, destination = rhivos-{VER}-gate
  • Create target rhivos-{VER}-test-pesign: same as candidate-pesign
  • Update rhivos-{RHEL_MAJOR}-newest-test-pesign to point to the new -test-pesign
  • Create Z-stream targets: same set with -z-

Configuration

  • Set %dist macro in build tags to .el{RHEL_MAJOR}iv (or .el{RHEL_MAJOR}_{RHEL_EUS}iv after branch point)
  • Set Brew build channel to rhel{RHEL_MAJOR}
  • Create dist-git branch rhivos-{VER} (stabilization branch, opens at RHEL branch point)
  • Configure dist-git gating policies for the new branch

Compose Configuration

  • Set up nightly compose latest-RHIVOS-{VER} sourcing from rhivos-{VER}-candidate
  • Set up RC compose pipeline for post-Dev Complete stabilization

Errata Tool

  • Create product release RHIVOS-{VER} (GA)
  • Create product release RHIVOS-{VER}.Z (z-stream)
  • Configure functional safety validator gating on advisories

8. Z-Stream Operations

After a RHIVOS release reaches GA, all new work moves to the Z-stream variant of the tags. The dist-git branch stays the same (e.g. rhivos-2.0 for both GA and z-stream).

Aspect GA Phase Z-Stream Phase
Build target rhivos-2.0-candidate rhivos-2.0-z-candidate
Dist-git branch rhivos-2.0 rhivos-2.0 (same branch)
Nightly compose latest-RHIVOS-2.0 from -candidate latest-RHIVOS-2.0 from -z-candidate
Errata release RHIVOS-2.0 RHIVOS-2.0.Z
RHEL inheritance Removed at Dev Complete Active from rhel-10.2-z
Jira fixVersion rhivos-2.0 rhivos-2.0.Xz (quarterly batch)

Z-Stream Update Types

  • Quarterly batches - scheduled updates using Errata Tool batches (e.g. RHIVOS-2.0.1, RHIVOS-2.0.2)
  • Asynchronous updates - individual advisories released outside the quarterly schedule
  • EUS updates - no separate product or release needed; uses the same batch and async mechanisms
