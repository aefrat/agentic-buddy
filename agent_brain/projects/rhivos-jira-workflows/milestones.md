# Timing Work to Program Milestones

RHIVOS tracks product-related changes against two key milestones per release.

## Dev Complete Milestone

- **Applies to:** Product work (Stories, Bugs, Weaknesses, Vulnerabilities)
- **Requirement:** Must be completed by the Dev Complete milestone for the given
  RHIVOS release.
- **Tracking:** No additional Fix Version in Jira. POs plan work against the
  release milestone Fix Version (e.g., rhivos-1.0).
- **Board:** Auto-All - Stories/Bugs board can generate a Version Report to
  monitor product work tracking to Dev Complete.
- POs may create their own filters/boards with just stories and tasks to track
  their functional area.

## Release Complete Milestone

- **Applies to:** Non-product work (Tasks)
- **Requirement:** Must be completed by the Release Complete milestone for the
  given release.
- **Tracking:** POs plan against the release milestone Fix Version (e.g.,
  rhivos-1.0).
- **Board:** Auto-All - no Epics board can generate a Version Report to monitor
  all planned work tracking to Release Complete.
- POs may use existing "version reports" for their functional area.

## Summary

| Milestone | Work Type | Issue Types |
|---|---|---|
| Dev Complete | Product work | Story, Bug, Weakness, Vulnerability |
| Release Complete | Non-product work | Task |

Tasks may also have earlier due dates set based on internal team milestones.
