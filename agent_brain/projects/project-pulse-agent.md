# Project Pulse Agent

Post-report intelligence layer that cross-references the manager report's Slack data against active project files. Runs as a follow-up step after each manager report (interactive only) or on demand.

## Goal

Connect daily operational signals — channel discussions, closed tickets, notable threads — back to the strategic project files. Ensure that project files stay current without requiring manual review of every Slack digest.

## Architecture

**Harness:** Claude Code (agentic-buddy) — runs as a skill triggered after the manager report.

**Identity:** Project intelligence analyst. Linker, not summarizer. Traces activity to projects it affects. Proposes sourced updates. Does not create new projects or restructure existing files.

**Input:** Manager report output (`/tmp/{mode}_report.html` + `/tmp/report_data.json` sidecar).

**Output:** Dated, sourced entries appended to project files in `agent_brain/projects/`.

### Data flow

```
generate_report.py → HTML + sidecar JSON
                         ↓
              project-pulse skill
                         ↓
            ┌────────────┴────────────┐
            │  agent_brain/projects/  │
            │  index.md → match map   │
            │  project files → verify │
            └────────────┬────────────┘
                         ↓
              user approval → update
```

### No separate memory stores

This agent reads the manager report's output (generated by a script — computed, not LLM-derived) and writes to existing project files. The projects themselves are the episodic store. No separate reference, active, or computed stores needed — the agent is stateless between runs.

## Design principles applied

| Principle | Application |
|-----------|------------|
| Identity & character | Intelligence analyst: linker, not summarizer. Evidence-based updates only. |
| Progressive disclosure | Read projects index first → open specific files only on match |
| Skill design | 7 steps + success criteria + gotchas + 10-item checklist |
| Disconfirmation gate | Step 4: verify each match is genuine — seek reasons to reject before accepting |
| Permissions | Append-only to project files. No restructuring. No new project creation. User approval required. |
| Tool design | Consumes script-generated report output (HTML + sidecar), not raw Slack API |
