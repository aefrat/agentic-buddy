## Manager report agent transformation (session 6)

- Seeded `patterns/writing-preferences.md` with capture structure (summary style, emphasis, avoid, tone)

### Decisions
- **Agent-as-wrapper pattern:** Python script stays as execution engine — never rewrite the data pipeline. The agent adds identity, memory, verification, and learning on top.
- **Shared team config:** Extended `qc-agent/team/members.yaml` additively rather than duplicating. Both agents read the same file; each ignores fields it doesn't use.
- **Sidecar output path:** Used function attribute (`build_report._sidecar_output`) to pass custom path without changing function signature — backward compatible.
- **Backward-compatible prompts:** `--stats-file` is optional. Without it, prompts use slightly improved identity language but no stats context. Cron jobs work unchanged.
- **Computed ≠ LLM:** Statistics (rolling averages, deltas, anomalies) are script-derived via `compute_stats.py`, never LLM-computed. "LLM statistics are plausible but wrong."

## System observations

- **Concept candidate:** "Agent-as-wrapper" pattern — wrapping an existing stateless script with agent harness (identity, memory, verification, learning) without rewriting the execution engine. The script handles data fetching and formatting; the agent adds context, comparison, and accumulation. Generalizable to any existing automation that works but doesn't learn. (seen: 1)
- **Concept candidate:** "Shared config, additive extension" — when two agents need overlapping team data, extend the existing config file with new fields rather than duplicating. Each agent ignores fields it doesn't use. Prevents config drift. Applied: QC agent's `members.yaml` extended with `accent_color` and `google_docs` for the manager report agent. (seen: 1)
