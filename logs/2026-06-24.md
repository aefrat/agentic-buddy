When I started editing, 10 of the 12 files were already committed with MCP changes from before compaction. The Edit tool succeeded silently (file already in desired state, git saw no diff). ## System observations (session 3)

- **Concept candidate:** "Context compaction idempotency trap" — after context compaction, the summary may list work as pending that was actually completed before compaction. The Edit tool accepts idempotent edits without error (old_string matches, new_string is identical to current content = no-op). Git shows no diff. Harmless but wasteful. Mitigation: after compaction, run `git log --oneline -1 -- <file>` to check if recent commits already contain the changes before re-applying. Related to the "context compaction data drift" observation from 2026-06-23. (seen: 1)
