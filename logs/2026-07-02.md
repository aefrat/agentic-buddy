## Lessons
- SBI framework works well when the positive intent is acknowledged within the Behavior section rather than as a separate softener - it makes the feedback feel more integrated and less like a "compliment sandwich."
- When constructing SBI feedback iteratively, new information from the recipient's perspective can fundamentally shift the core issue. Kanitha's clarification (she did ask permission) meant the problem wasn't about sharing - it was about the precision of language. The lesson: don't lock in the SBI framing too early; be ready to rewrite the Behavior section entirely when you learn the other side's account.
- gws drive files create requires `--upload` flag (not `--media`) for file upload with `--upload-content-type` for MIME type. The `--params` JSON with `mimeType: application/vnd.google-apps.document` does not trigger HTML-to-Docs conversion - files upload as raw HTML. Renaming requires a separate `gws drive files update` call since name in `--params` is ignored during create.
- Gmail send with large HTML attachments can exceed shell argument list limits. For large attachments, either send as separate emails or use Drive links instead of inline attachments.
- Context compaction mid-session requires careful state reconstruction - the session was split across two context windows. Key data (research findings, Jira results, Google Doc exports) had to be carried via the summary since the original tool results were lost.

## System observations
- **Concept candidate:** "Policy enforcement vs process requirement separation" - dist-git policy enforcement (server-side commit hooks) and errata ticket requirements (advisory generation) are independent systems that address different concerns. Disabling one doesn't remove the need for the other. Generalizable: any automated enforcement gate that gets disabled still leaves the business process requirement intact. The automation just makes it mandatory; without it, the requirement becomes tribal knowledge and gets missed.
- **Skill candidate:** "Large-scale agent+skill+deliverable creation" - multi-phase pattern: (1) parallel research agents for external data, (2) knowledge base scaffolding, (3) parallel agents for skill + reference file creation, (4) parallel agents for HTML deliverables, (5) registration + delivery. This session spawned 6+ parallel agents across phases. Could generalize into a "create agent from requirements" meta-skill. (seen: 1)
- **Concept candidate:** "Three-tier progressive criteria model" - each release milestone is a strict superset of the previous one, with measurable pass/fail conditions per criterion. Adapted from RHIVOS CTC (two-phase: Reduced then Full) and OCP (EC/RC/GA builds). The progressive superset pattern avoids the common failure mode of defining GA criteria that are disconnected from intermediate milestones. (seen: 1)
