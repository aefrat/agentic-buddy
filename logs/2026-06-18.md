### Key findings from the rollup demo (Jun 17):

**Three distinct AI agent approaches emerging in the org:**

1. **FoA Config Validator Workflow** (Gadi Glogowski / Rajesh Srivastava) — Claude Code-based, end-to-end Jira→MR automation with 5-layer defense-in-depth safety, 9 specialized skills, 8 presubmit quality gates. Currently in personal fork, moving to shared repo.

2. **AAA Stateful Process Agent** (Juanje Ojeda) — Pi-based (model-agnostic), focused on infrastructure debugging not code writing. "The repo IS the agent." 6 design principles including character-over-rules, progressive disclosure, 4-store memory architecture, disconfirmation gates.

3. **AIIL Issue-to-Release** (Michael Kuehl) — outer-loop counterpart orchestrating issue→build→test-on-hardware with AI-driven remediation. Already tracked in `aiil-demo-rhas.md`.

**Cross-cutting consensus from the discussion:**
- File-based transparent memory (markdown) beats opaque memory
- Hooks are essential for memory capture — models don't remember autonomously
- Memory compaction (daily→weekly→monthly) prevents contradictions
- The harness (identity + memory + procedures + tools + permissions) is what separates useful agents from chatbots
