## Lessons
- GitLab runner executor config is on the host machine (`config.toml`), not configurable via GitLab UI. Registration location (user vs system) depends on how `gitlab-runner register` was invoked (with or without sudo).
- Podman's Docker-compatible socket (`podman.socket`) enables GitLab's Docker executor to work with Podman without changing executor type. Rootful socket needed when runner runs as system service.
- Multiple `host =` lines in TOML `[runners.docker]` section - last value wins in some parsers, but it's ambiguous. Always ensure only one.
- `DOCKER_AUTH_CONFIG` CI variable provides runner-level auth for image pulls from private registries. Value format: `{"auths":{"registry":{"auth":"base64(user:token)"}}}`. Must use `echo -n` (not `echo`) for base64 to avoid trailing newline.
- `glab ci run` triggers with `source: api`, not `source: web`. CI rules matching only `web` won't see API-triggered pipelines.
- GCP project API enablement is per-API: Vertex AI enabled doesn't mean Google Docs API is enabled. Each must be explicitly activated.
- Claude on Vertex AI (AnthropicVertex) requires model availability in the GCP project/region via Model Garden. Gemini is available by default with Vertex AI enabled.
- quay.io "public" means internet-public, not org-scoped. No "Red Hat internal only" visibility option exists on quay.io.
