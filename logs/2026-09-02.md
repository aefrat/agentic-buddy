## Lessons
- **bootc/image-mode vs package-mode is the fault line for "can Konflux build this VM?"** Konflux's only disk-image path (`build-vm-image` = bootc-image-builder) takes a bootc container and emits an image-mode (ostree, immutable) system - read-only `/usr` and `/`, no persistent `dnf`. It cannot produce a mutable, package-managed ("package mode") VM no matter what output format you request; that requires plain osbuild/Image Builder blueprints (the Brew path). The bootc->qcow conversion never changes the input's immutable nature. So "build a mutable VM" and "build via Konflux" are mutually exclusive by construction, not by tooling maturity. Generalizable: when someone says "we'll eventually move X to Konflux," check whether X is image-mode-compatible first - the org direction assumes bootc, and a mutable artifact can't follow it without a UX redesign.
- **Verify a colleague's technical constraint against authoritative docs before scoping around it.** Juanje's "Konflux can't build a mutable image" was a load-bearing claim (it kills a whole build path). Checking it against bootc/BIB/image-mode docs confirmed it AND surfaced the precise mechanism (composefs read-only root, BIB image-mode-only output, transient-root only runtime-writable), which is more actionable than the bare claim - it tells you exactly which knobs were considered and why they don't help. Confirming a claim is cheap insurance when the claim determines the plan.
- **Linkify-after-escape must be idempotent.** When post-processing already-HTML-escaped text to inject `<a>` links for ticket keys, guard against re-wrapping keys that are already inside a link (a browse URL or anchor text). Used negative lookbehinds (`(?<!browse/)(?<!>)`) so the same helper is safe to apply over structured cells that already contain explicit links, and safe to run twice. Verified by an idempotency unit test plus a "no bare reference" invariant test over the full rendered HTML — a stronger guarantee than testing individual call sites.
